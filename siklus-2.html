Modul Ajar Siklus 2: Algoritma, Flowchart & Pseudocode

Penerapan model Problem-Based Learning (PBL) untuk memecahkan kasus percabangan multi-kondisi melalui representasi grafis dan tekstual.

Dokumen Lengkap
Model Pembelajaran Problem-Based Learning (PBL)
Standar Diagram ISO 5807 Flowchart Notation
Struktur Logika Sequential & Branching (IF-ELSE)
Metode Verifikasi Uji Jejak Kering (Dry Run Table)

Sintaks Pembelajaran Problem-Based Learning:

1. ORIENTASI MASALAH (15 Menit): - Guru menyajikan kasus sistem kasir minimarket: "Kapan pembeli mendapat diskon 15%?" - Siswa menganalisis kondisi: Total belanja > Rp 100.000 DAN memiliki kartu member. 2. MENGORGANISASI SISWA (15 Menit): - Pembagian kelompok heterogen 4 siswa untuk memetakan simbol flowchart (Terminator, Input, Decision, Output). 3. MEMBIMBING PENYELIDIKAN (30 Menit): - Siswa mendesain flowchart dan menulis pseudocode terstruktur di LKPD. - Guru melakukan scaffolding pada kelompok yang mengalami kebuntuan percabangan ganda. 4. MENGEMBANGKAN & MENYAJIKAN HASIL (20 Menit): - Pengujian alur menggunakan Trace Table (Dry Run) dengan variasi nilai input acak. - Perwakilan kelompok mempresentasikan ke depan kelas. 5. EVALUASI PROSES PEMECAHAN MASALAH (10 Menit): - Konfirmasi validitas algoritma dan kuis formatif penelusuran error logika (bug trace).

Rubrik Penilaian Kinerja Algoritma (4 Aspek):

INDIKATOR PENILAIAN ALGORITMA (TOTAL 100 POIN): 1. Ketepatan Simbol ISO (Bobot 25%): - Menggunakan Oval (Terminator), Jajar Genjang (I/O), Persegi Panjang (Proses), Belah Ketupat (Kondisi Decision). 2. Kelogisan Alur Percabangan (Bobot 30%): - Memiliki cabang YA dan TIDAK yang terdefinisi tuntas tanpa loop tak hingga (infinite loop). 3. Struktur Notasi Pseudocode (Bobot 25%): - Menggunakan kata kunci terstandar: INPUT, IF...THEN...ELSE, ENDIF, OUTPUT. 4. Validitas Hasil Uji Jejak (Bobot 20%): - Tabel simulasi dry run menghasilkan output yang 100% konsisten dengan skenario uji kasus.

LKPD Praktik: Perancangan Flowchart & Uji Trace Table

Panduan praktikum terarah merancang diagram alir sistem diskon belanja dan penentuan grade nilai siswa di SMA Negeri 4 Yogyakarta.

Unduh Lembar Kerja
Format Penugasan Kelompok (4 Siswa)
Perangkat Lunak Draw.io / Kertas Plano Milimeter
Waktu Praktik 40 Menit Terfokus
Target Output Flowchart Valid & Trace Selesai

Penugasan Kasus Nyata LKPD Siklus 2:

STUDI KASUS LKPD S2: "Sistem Logika Kasir Otomatis Koperasi Siswa SMAN 4 Yogyakarta" SKENARIO LOGIKA: 1. Input: Nama Pembeli, Total Belanja, Status Kartu Anggota (YA/TIDAK). 2. Ketentuan: - Jika Total Belanja >= Rp 100.000 DAN Anggota = YA, Diskon = 15%. - Jika Total Belanja >= Rp 100.000 DAN Anggota = TIDAK, Diskon = 5%. - Selain itu, Diskon = 0%. 3. Output: Total Akhir yang Harus Dibayar. 4. TUGAS: - Buat Flowchart lengkap dengan simbol ISO! - Tuliskan notasi pseudocode-nya! - Uji dengan 3 set data acak pada Tabel Dry Run yang telah disediakan.

1. Kekuatan Pembelajaran

Penggunaan metode Dry Run (Trace Table) terbukti sangat manjur membantu siswa menemukan sendiri kesalahan logika (*self-debugging*) sebelum diagram dipresentasikan, meningkatkan ketuntasan belajar hingga 91.7%.

2. Kendala / Tantangan

Beberapa siswa masih tertukar antara simbol Proses (Persegi Panjang) dan Input/Output (Jajar Genjang) ketika menulis instruksi pembacaan data diskon dari kasir.

3. Rencana Tindak Lanjut

Melanjutkan ke Siklus 3 (Analisis Data & Excel) dengan memanfaatkan logika formula IF dan LOOKUP langsung ke tabel spreadsheet riil agar pemahaman logika komputasional siswa terimplementasikan secara praktis.
